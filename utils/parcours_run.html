Parcours d'un run

Les étapes typiques d'un run, de python -m agents au rapport final.

  1. Lancement code

    python -m agents démarre l'orchestrateur, avec l'objectif --goal comme premier message, et trois budgets :

    • --budget-usd (1 $ par défaut) : budget API partagé par les 4 agents. 15 % sont mis de côté pour le rapport final de l'orchestrateur (0,15 $ sur 1 $).
    • --data-budget (250) : nombre de vidéos générables pendant la session. Seules les vidéos réussies sont décomptées.
    • --final-tests (2) : nombre d'appels à final_test, le seul accès au split test.

  2. L'orchestrateur lit l'état du projet agent · orchestrator

    Son prompt lui demande de lire l'état avant de décider. En pratique, son premier tour appelle :

    • global_status : état du dataset (clips générés, rushes bruts uniques, frames, splits, vidéos générables et tests finaux restants) et $ dépensés ;
    • list_experiments : toutes les expériences passées, de toutes les sessions. Un run ne repart donc pas de zéro.
