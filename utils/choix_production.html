Choix du modèle de production

Fait par le code à la fin de chaque run (lab.select_production), jamais par un agent. Les agents préparent les candidats ; le code applique toujours la même règle.

Pendant le run · les agents préparent les candidats

Model Researcher · train_model

Entraîne une expérience sur le dernier split et la mesure sur val (validation croisée par chaîne : chaque image est prédite par un modèle qui n'a jamais vu sa chaîne). Le code y fixe le seuil prudent qui tient 95 % de précision (200 tirages de chaînes, 80e centile), enregistré avec l'expérience.

Evaluator · final_test

Teste candidat_a_tester (donné par list_experiments : la règle de l’étape 3 appliquée aux non testés), un à la fois, 2 par run au plus : ce même seuil sur le test du split, des chaînes jamais vues. Précision ≥ 95 % → réussi, on s'arrête ; sinon échoué, et le candidat suivant prend sa place. Sans test → non testé.

Fin du run · le code choisit

1Le plus gros split

Seules comptent les expériences du split qui a le plus de vidéos (le plus récent, en pratique).

↓

2Les candidats, selon leur test final

On ne compare que des modèles qui en sont au même point du test final :

  • si au moins un modèle a réussi son test, on choisit seulement parmi eux : un modèle vérifié passe toujours devant un modèle qui ne l'est pas ;
  • sinon, parmi ceux qui n'ont pas été testés : ils peuvent encore tenir leurs 95 % ;
  • en dernier recours seulement, parmi ceux qui ont échoué leur test.
↓

3Le meilleur du groupe

On garde ceux dont l'AP par chaîne sur val est à moins de 0,005 de la meilleure (ils reconnaissent aussi bien les ajouts sur des chaînes nouvelles), puis on prend celui qui a le meilleur rappel sur val (la part des ajouts trouvés, au seuil qui tient 95 % de précision).
